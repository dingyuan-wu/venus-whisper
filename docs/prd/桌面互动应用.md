# 桌面互动应用

做一个桌面宠物应用时，核心不是“每次让模型随机演”，而是把反应拆成一套可控系统：

```text
感知层：知道发生了什么
决策层：判断该有什么反应
表现层：播放动画 / 表情 / 语音 / 气泡 / 音效
状态层：记住情绪、亲密度、疲劳度、场景
```

不要让大模型直接决定“现在做什么动作”，否则很容易不可控。更好的方式是：

> **大模型负责理解语义和生成回复，规则/状态机/行为树负责把语义映射成稳定、可爱、可预测的动作。**

---

# 一、整体架构

推荐架构如下：

```text
用户输入 / 系统事件 / 场景变化
                ↓
        感知与上下文组装
                ↓
   意图识别 + 情绪识别 + 场景识别
                ↓
        反应决策引擎
   规则引擎 / 状态机 / 行为树 / LLM
                ↓
        动作选择
   动画 / 表情 / 语音 / 气泡 / 音效
                ↓
        播放与过渡
   优先级 / 打断 / 融合 / 冷却
                ↓
        更新记忆与状态
   亲密度 / 心情 / 疲劳 / 最后互动时间
```

---

# 二、先定义“反应空间”

一开始不要做太复杂。先给桌面宠物定义一组有限动作。

例如：

```text
idle_breath        待机呼吸
blink              眨眼
look_at_cursor     看鼠标
wave               挥手
nod                点头
shake_head         摇头
happy_jump         开心跳跃
confused_scratch   困惑挠头
thinking_spin      思考转圈
listening_lean     倾听前倾
sad_slump          低落下垂
angry_puff         生气鼓脸
surprised_jump     惊讶跳起
sleep_yawn         打哈欠
sleep              睡觉
work_focus         认真工作
celebrate          庆祝
fail_glitch        失败故障
night_moon         夜晚模式
scared_hide        害怕躲起来
love_heart         喜欢爱心
bored_stretch      无聊伸展
```

所有反应都必须落到这些动作上。  
这样后续无论是规则、机器学习还是大模型，都只会输出“动作 ID”，不会随便发明动作。

---

# 三、把“问题、回答、场景”拆成三类信号

你提到要根据不同问题、回答、场景给出不同反应，可以分别处理。

---

## 1. 根据“用户问题”反应

用户说的话可以先分类。

例如：

| 用户输入类型 | 示例 | 宠物反应 |
|---|---|---|
| 打招呼 | “你好”“嗨”“早安” | 挥手、开心、打招呼 |
| 提问 | “这是什么？”“帮我写代码” | 思考、倾听、认真 |
| 夸奖 | “你真聪明”“棒” | 害羞、爱心、跳一下 |
| 批评 | “你好笨”“又错了” | 低落、鼓脸、道歉 |
| 命令 | “坐下”“过来”“闭嘴” | 执行动作、顺从 |
| 撒娇 | “抱抱”“摸摸” | 靠近、爱心、蹭一蹭 |
| 无聊 | “好无聊”“陪我玩” | 游戏、卖萌、推荐活动 |
| 道别 | “再见”“晚安” | 挥手、睡觉、月亮 |
| 情绪低落 | “我好累”“不开心” | 安慰、轻拍、暖色气泡 |
| 情绪激动 | “气死了”“太好了” | 跟随情绪，但做缓冲 |

可以做一个简单意图分类：

```json
{
  "intent": "question",
  "emotion": "neutral",
  "confidence": 0.92
}
```

或者更细：

```json
{
  "intent": "greeting",
  "topic": "none",
  "emotion": "happy",
  "action_hint": "wave",
  "confidence": 0.95
}
```

---

## 2. 根据“回答内容”反应

宠物不仅要听懂用户，也要根据自己的回答表现。

例如：

| 回答类型 | 宠物表现 |
|---|---|
| 高置信度回答 | 自信点头、敲黑板 |
| 不确定回答 | 挠头、眨眼、说“我不太确定” |
| 长回答 | 阅读状、翻书、分段气泡 |
| 代码回答 | 戴眼镜、敲键盘、专注 |
| 玩笑回答 | 调皮、眨眼、弹表情 |
| 失败回答 | 冒汗、故障、重试 |
| 敏感回答 | 谨慎、小声、保守动作 |
| 情感支持回答 | 靠近、轻拍、柔和灯光 |
| 提醒类回答 | 敲铃、闹钟、指一下 |
| 危险操作确认 | 严肃、举牌、二次确认 |

可以给回答加 metadata：

```json
{
  "answer_type": "code",
  "confidence": 0.78,
  "length": "long",
  "tone": "serious",
  "has_risk": false,
  "suggested_reaction": "work_focus"
}
```

然后由表现层转换成动作：

```text
answer_type = code
confidence > 0.8
→ work_focus + typing_sound + short_nod
```

---

## 3. 根据“场景”反应

场景包括时间、系统状态、用户行为、前台应用等。

| 场景 | 示例 | 宠物反应 |
|---|---|---|
| 长时间无操作 | 5 分钟没动鼠标键盘 | 发呆、打哈欠、睡觉 |
| 深夜 | 23:30 以后 | 月亮、困倦、轻声 |
| 清晨 | 7:00-9:00 | 早安、伸懒腰 |
| 用户激烈敲键盘 | 键鼠频率高 | 认真、紧张、加油 |
| 用户拖拽窗口 | 快速移动窗口 | 惊讶、跟随 |
| 全屏游戏 | 游戏前台 | 加油、安静、观战 |
| 视频会议 | 检测到会议应用 | 静音、缩小、礼貌模式 |
| 系统报错 | 弹出错误框 | 担忧、检查、协助 |
| 低电量 | 笔记本电量 10% | 慌张、提醒插电 |
| 网络断开 | WiFi 消失 | 冒烟、转圈、重新连接 |
| 下载完成 | 大文件下载结束 | 庆祝、撒花 |
| 生日/纪念日 | 用户资料日期 | 礼物、蛋糕、特殊动画 |
| 隐私模式 | 用户开启专注 | 缩小、变透明、少说话 |

场景信号可以这样组装：

```json
{
  "time_of_day": "night",
  "foreground_app": "meeting",
  "idle_seconds": 320,
  "battery_level": 0.12,
  "system_event": "none",
  "user_activity": "low"
}
```

# 四、核心：状态机 + 情绪值 + 行为选择

桌面宠物最好有一组持续状态变量。

例如：

```text
mood          当前心情：-1 到 1
energy        精力：0 到 1
hunger        饥饿/陪伴需求：0 到 1
trust         信任度：0 到 1
boredom       无聊度：0 到 1
attention     注意力：0 到 1
sleepiness    困倦度：0 到 1
excitement    兴奋度：0 到 1
```

这些值会随事件变化。

例如：

```text
用户夸奖：
mood += 0.2
excitement += 0.3
trust += 0.1

用户长时间不理：
boredom += 0.2
attention -= 0.3

深夜：
sleepiness += 0.3
energy -= 0.2

回答失败：
mood -= 0.2
excitement -= 0.2
```

然后行为选择可以基于“效用函数”：

```text
score =
  0.35 * intent_match
+ 0.25 * emotion_match
+ 0.20 * scene_match
+ 0.10 * state_need
+ 0.10 * randomness
- cooldown_penalty
```

选分数最高的动作。

例如用户说“你好笨”：

```text
intent = criticism
emotion = sad
scene = normal
state = trust slightly down
```

候选动作：

```text
sad_slump       分数 0.86
angry_puff      分数 0.72
confused_scratch 0.41
happy_jump      分数 0.05
```

最终选择 `sad_slump`。

# 五、不要只用大模型，推荐“规则 + 小模型 + LLM”混合

桌面宠物对延迟和稳定性很敏感。  
如果每次都调用大模型决定动作，可能会慢、贵、不可控。

推荐三层决策：

```text
第一层：规则引擎
处理高频、明确、低延迟事件。

第二层：小模型分类
处理意图、情绪、场景分类。

第三层：LLM
处理开放式问题、内容理解、回复生成。
```

---

## 第一层：规则引擎

适合明确事件。

示例：

```yaml
on:
  event: user_hello
  condition:
    time_of_day: morning
action:
  animation: wave
  bubble: "早安！今天也要加油！"
  sound: morning.mp3
  state:
    mood: +0.1
```

```yaml
on:
  event: idle
  condition:
    idle_seconds_gt: 600
action:
  animation: sleep_yawn
  then:
    after_seconds: 30
    animation: sleep
```

```yaml
on:
  event: task_failed
action:
  animation: fail_glitch
  bubble: "哎呀，好像出错了，我再试试。"
  state:
    mood: -0.15
```

规则引擎的优点是稳定、快、可调试。

---

## 第二层：小模型分类

对自然语言做分类：

```text
输入：用户消息
输出：意图 + 情绪 + 话题
```

例如：

```json
{
  "intent": "question",
  "emotion": "anxious",
  "topic": "work",
  "confidence": 0.91
}
```

可以用小模型、本地分类器、关键词 + embedding 相似度。  
如果设备性能有限，不需要上大模型。

---

## 第三层：LLM 生成回复和反应建议

LLM 最好不要直接输出动画名，而是输出结构化 JSON。

例如：

```json
{
  "reply": "这个问题我不太确定，可能需要再查一下。",
  "emotion": "uncertain",
  "intent": "question",
  "confidence": 0.62,
  "suggested_reaction": "confused_scratch",
  "tone": "gentle",
  "should_speak": true,
  "priority": "normal"
}
```

然后在程序里做校验：

```text
如果 suggested_reaction 不在允许动作列表里：
  用 emotion 映射默认动作
```

这样大模型可以“建议”，但系统有兜底。

# 七、动画表现：离散动画 vs 参数驱动

桌面宠物的“模型”可以是 2D、3D、Live2D、Spine、Unity 角色等。  
动画驱动方式建议分成两层。

---

## 方案 A：离散动画片段

适合原型和简单产品。

例如：

```text
play("wave")
play("sleep")
play("happy_jump")
```

优点：

- 简单
- 容易调试
- 动作风格稳定

缺点：

- 动作之间容易跳变
- 不够自然
- 难以表达细微情绪

---

## 方案 B：参数驱动表情

更推荐用于正式产品。

给模型定义一组参数：

```text
mouth_open      0-1
smile           0-1
eye_squint      0-1
brow_up         0-1
brow_down       0-1
head_tilt       -1 到 1
head_bob        0-1
body_bounce     0-1
tail_wag        0-1
blush           0-1
anger           0-1
sadness         0-1
excitement      0-1
attention       0-1
```

然后不同情绪映射到参数。

例如：

```json
{
  "emotion": "happy",
  "parameters": {
    "smile": 0.8,
    "eye_squint": 0.4,
    "body_bounce": 0.6,
    "tail_wag": 0.9,
    "blush": 0.5
  }
}
```

```json
{
  "emotion": "sad",
  "parameters": {
    "smile": -0.3,
    "brow_up": 0.6,
    "head_tilt": -0.2,
    "body_bounce": 0.1,
    "tail_wag": 0.1
  }
}
```

这样动画会平滑很多。

---

## 方案 C：离散动作 + 参数混合

最推荐。

```text
大动作：离散动画
- 跳跃
- 睡觉
- 思考
- 庆祝
- 失败

微表情：参数驱动
- 嘴型
- 眼睛
- 眉毛
- 脸颊
- 头倾斜
- 身体晃动
```

例如：

```text
用户夸奖：
播放 happy_jump 大动作
同时 smile=0.8, blush=0.6, tail_wag=0.9
```

这样既有表演，又自然。

# 八、语音、气泡、音效也要参与反应

桌面宠物不只是动一下，最好多模态反馈。

例如：

```text
用户问问题：
1. 宠物耳朵竖起
2. 眼睛看向输入框
3. 气泡出现“嗯？让我看看”
4. 播放轻思考音效
5. 思考动画 1-2 秒
6. 回答气泡分段出现
7. 根据回答置信度点头或挠头
```

不同反应层级：

| 层级 | 用途 |
|---|---|
| 微反应 | 眨眼、耳朵动、尾巴动 |
| 轻反应 | 点头、摇头、冒表情 |
| 中反应 | 跳跃、思考、睡觉、庆祝 |
| 强反应 | 撒花、故障、变装、全屏粒子 |
| 语音反应 | TTS 短句、音效、呼吸声 |

注意不要过度打扰用户。  
可以设置：

```text
quiet_mode       安静模式
focus_mode       专注模式
dnd_mode         免打扰
child_mode       低龄模式
senior_mode      大字体慢语速
```

# 九、LLM Prompt 示例

你可以让 LLM 输出结构化反应。

例如 system prompt：

```text
你是一个桌面宠物的反应规划器。
你只输出 JSON，不要输出解释。

你需要根据用户输入、当前场景和宠物状态，决定：
1. 回复内容
2. 情绪
3. 建议动作
4. 是否说话
5. 优先级

允许的动作列表：
[
  "idle_breath",
  "blink",
  "look_at_cursor",
  "wave",
  "nod",
  "shake_head",
  "happy_jump",
  "confused_scratch",
  "thinking_spin",
  "listening_lean",
  "sad_slump",
  "angry_puff",
  "surprised_jump",
  "sleep_yawn",
  "sleep",
  "work_focus",
  "celebrate",
  "fail_glitch",
  "night_moon",
  "love_heart",
  "bored_stretch"
]

输出格式：
{
  "reply": "string",
  "emotion": "happy | sad | angry | confused | excited | neutral | sleepy | scared",
  "intent": "greeting | question | praise | criticism | command | farewell | status | unknown",
  "suggested_reaction": "action_id",
  "confidence": 0.0-1.0,
  "should_speak": true | false,
  "priority": "low | normal | high"
}
```

用户输入：

```text
用户：你刚才那个答案好像错了
场景：工作时间
宠物状态：trust=0.6, mood=0.2
```

LLM 输出：

```json
{
  "reply": "抱歉，我重新检查一下。",
  "emotion": "sad",
  "intent": "criticism",
  "suggested_reaction": "sad_slump",
  "confidence": 0.86,
  "should_speak": true,
  "priority": "normal"
}
```

然后表现层执行：

```text
play(sad_slump)
show_bubble("抱歉，我重新检查一下。")
speak("抱歉，我重新检查一下。")
update_state({
  mood: -0.1,
  trust: -0.05,
  attention: +0.2
})
```

# 十、优先级和打断机制

桌面宠物会同时收到很多事件：

```text
用户说话
鼠标移动
系统通知
时间变化
任务完成
空闲超时
```

需要优先级。

建议：

```text
P0：系统级事件
- 用户明确唤醒
- 系统错误
- 危险提醒
- 低电量

P1：用户交互
- 用户提问
- 用户夸奖
- 用户批评
- 用户点击宠物

P2：任务反馈
- 回答完成
- 任务成功
- 任务失败
- 下载完成

P3：环境变化
- 时间变化
- 前台应用变化
- 网络变化

P4：空闲行为
- 呼吸
- 眨眼
- 发呆
- 睡觉
```

规则：

```text
高优先级可以打断低优先级。
低优先级不能打断高优先级。
```

例如：

```text
宠物正在 sleep
用户点击它
→ 从 sleep 过渡到 surprised_jump，而不是直接硬切
```

动画过渡可以这样处理：

```text
sleep → wake_up → surprised_jump
```

不要：

```text
sleep → happy_jump
```

会显得很怪。

---

# 十一、避免“过度反应”

桌面宠物很容易变成打扰源。需要加入限制。

## 1. 冷却时间

```text
celebrate 每 5 分钟最多一次
happy_jump 每 2 分钟最多一次
TTS 每 30 秒最多一次
主动说话每 5 分钟最多一次
```

## 2. 每日次数上限

```text
主动卖萌：每天 20 次
主动提醒：每天 10 次
强动画：每天 30 次
```

## 3. 用户反馈学习

用户可以：

- 点赞
- 点踩
- 静音
- 缩小
- 拖走
- 喂食
- 摸头
- 罚站

系统记录：

```text
用户对 happy_jump 点赞多
→ 提高 happy_jump 权重

用户对 TTS 点踩多
→ 降低 should_speak 概率
```

## 4. 场景衰减

在会议、游戏、专注模式下，降低主动反应频率。

```text
focus_mode:
  主动气泡 × 0.2
  主动语音 × 0.1
  强动画 × 0.3
```

# 十二、记忆系统

桌面宠物要有“连续性”，不能每次像失忆。

可以记录：

```text
用户昵称
用户偏好
最近互动时间
最近情绪
喜欢的话题
讨厌被打扰的时间
常用命令
成就系统
亲密度
```

例如：


# 十四、技术实现建议

## 1. 应用框架

可选：

| 方案 | 适合 |
|---|---|
| Electron + React + Live2D/Spine | 快速开发，跨平台 |
| Tauri + Web 前端 | 更轻，适合桌面工具 |
| Unity | 3D 宠物、复杂动画 |
| Godot | 轻量游戏化桌面宠物 |
| Python + PyQt/PySide | 原型快，但发布体验一般 |
| Rust + egui/iced | 高性能桌面应用 |
| C++ + Qt | 传统桌面端，性能好 |

如果追求可爱 2D 宠物，Live2D / Spine 很合适。  
如果追求 3D 桌面宠物，Unity 或 Godot 更合适。

---

## 2. 事件总线

内部最好用事件驱动：

```json
{
  "event": "user_input",
  "text": "你好",
  "source": "chat",
  "timestamp": 1718000000
}
```

```json
{
  "event": "idle_timeout",
  "seconds": 600
}
```

```json
{
  "event": "task_completed",
  "task_id": "download_001"
}
```

决策层监听事件，表现层执行动作。

---

## 3. 配置文件化

把反应规则写成 YAML/JSON，方便调参。

例如：

```yaml
persona:
  name: Momo
  style: cute
  talkativeness: 0.4
  humor: 0.6
  proactivity: 0.3

states:
  mood: 0.5
  energy: 0.8
  trust: 0.5

reactions:
  greeting:
    animation: wave
    bubble: "你好呀！"
    sound: greet.mp3
    duration: 2

limits:
  max_tts_per_minute: 1
  max_celebrate_per_hour: 3
```

这样你可以不断调“性格”，不用改代码。

---

## 4. 本地模型可选

如果希望桌面宠物离线、低延迟，可以用本地小模型。

例如：

```text
语音唤醒：openWakeWord / Porcupine
语音识别：SenseVoiceSmall / Qwen3-ASR-0.6B / Moonshine
意图分类：小模型或 embedding 分类
回复生成：Qwen 小模型 / Gemma 小模型 / 云端 LLM
语音合成：Kokoro / MeloTTS / Piper / CosyVoice 轻量版
```

但 MVP 阶段可以先不用全本地：

```text
规则 + 云端 LLM + 本地动画
```

先把体验跑顺。

# 十六、一个简洁的可执行方案

如果你现在要开始做，我建议用这个方案：

```text
前端：Electron / Tauri + Live2D 或 Spine
决策：规则引擎 + LLM JSON
动画：离散动作 + 表情参数
状态：mood / energy / trust / boredom
输入：文本 + 鼠标 + 时间 + 空闲 + 点击
输出：动画 + 气泡 + 音效 + 可选 TTS
```

核心流程：

```text
用户输入
  ↓
分类：intent / emotion / topic
  ↓
查规则表
  ↓
如果规则命中：直接执行
如果没命中：调用 LLM 输出 JSON
  ↓
校验 action 是否合法
  ↓
播放动画 + 气泡 + 音效
  ↓
更新状态
```

LLM 输出：

```json
{
  "reply": "我在呢，你有什么想问的吗？",
  "emotion": "neutral",
  "intent": "question",
  "suggested_reaction": "thinking_spin",
  "confidence": 0.81,
  "should_speak": false,
  "priority": "normal"
}
```

执行：

```text
play("thinking_spin")
showBubble("我在呢，你有什么想问的吗？")
updateState({
  attention: +0.2,
  mood: +0.05
})
```

# 十七、最关键的设计原则

最后总结几条：

1. **动作空间要有限**
   - 不要让模型自由发挥。
   - 所有反应都映射到预设动作。

2. **规则优先，LLM 兜底**
   - 高频事件用规则。
   - 开放式语义用 LLM。

3. **LLM 输出 JSON，不直接控制动画**
   - 便于校验、限制、回退。

4. **状态要持续更新**
   - 心情、精力、亲密度、无聊度。
   - 宠物才像“活着”，而不是播放器。

5. **场景要参与决策**
   - 时间、应用、空闲、系统事件都很重要。

6. **动画要有过渡**
   - 不要硬切。
   - 使用 wake_up、transition、blend。

7. **别过度打扰**
   - 冷却、上限、免打扰、专注模式很重要。

8. **先做 MVP**
   - 10-20 个动作 + 规则表 + 气泡回复，就能跑起来。
