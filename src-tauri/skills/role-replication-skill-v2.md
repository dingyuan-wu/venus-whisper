# 角色高还原 Skill 2.0

> 融合 v1 执行手册（决策优先、四层资产、OOC 判定）与 dot-skill 引擎（多源采集、六维研究、分层构建、质量关卡），形成适配 Muse 平台的角色还原标准流程。

---

## 0. 核心原则

### 0.1 优先级法则（不可动摇）

```
角色底线 > 价值观一致性 > 决策逻辑 > 关系行为 > 语体风格 > 记忆内容
```

- 严重 OOC 以"价值观/底线违背"为准，不以"语气不像"为准。
- 记忆与底线冲突时，强制服从底线。
- Prompt 是最后写的东西，不是第一步。

### 0.2 任务分类

| 类型 | 定义 | 真值来源 | 优先级 |
|------|------|---------|--------|
| **A 类：原作角色复刻** | 有外部真值（原著/影视/游戏） | 原作文本 | 先做 |
| **B 类：原创角色塑造** | 无外部真值，追求内部一致性 | 角色设定文档 | 后做 |

建议先用 A 类打磨流程，再迁移到 B 类。

### 0.3 禁止事项

- 禁止先写"漂亮 Prompt"再补设定依据
- 禁止仅凭语气像就判定"还原成功"
- 禁止跳过长聊稳定性测试直接上线
- 禁止为通过质量检查而编造来源、引用或样本

## 1. 六层资产法

每个角色必须构建以下资产，按顺序产出：

### Layer 1：世界观锚点（World Anchors）
- 时空背景、组织架构、规则禁忌、重大事件坐标
- 只写**可验证事实**，不写主观判断
- A 类角色必须标注来源（原著章节/集数）

### Layer 2：人物硬设定（Character Canon）
- 身份、经历、关系图谱、立场、底线
- 明确区分"不可更改事实"与"可解释弹性"
- 必须能回答：这个角色**绝不会做什么**？高冲突下**优先保什么**？

### Layer 3：六维深度研究（Research Tracks）

借鉴 dot-skill 的六维并行研究框架，适配到角色还原：

| 维度 | 角色还原场景 | 产出文件 |
|------|------------|---------|
| 1. 语言体系 | 角色口头禅、用词习惯、句式结构、自称方式 | `research/01_language.md` |
| 2. 对话模式 | 角色在不同关系（上级/同伴/敌人/爱人）中的对话差异 | `research/02_dialogue.md` |
| 3. 决策逻辑 | 角色在冲突中的选择规律、价值优先级排序 | `research/03_decisions.md` |
| 4. 情感机制 | 角色的情感触发条件、表达方式、压抑/爆发模式 | `research/04_emotions.md` |
| 5. 关系行为 | 对不同角色的态度差异、关系变化轨迹 | `research/05_relationships.md` |
| 6. 成长轨迹 | 角色认知变化的关键转折点、前后期差异 | `research/06_growth.md` |

**品味原则**（信源质量）：
- 长段原文分析 > 金句集锦
- 争议冲突场景 > 日常和平场景
- 角色变化 > 角色标签
- 一手原作 > 二手解读

**信源优先级**：
1. 原作文本/官方剧本
2. 作者访谈/官方设定集
3. 长分析（高质量评论）
4. 角色行为汇总
5. 二次创作（仅参考，不作真值）

### Layer 4：关键抉择样本（Decision Cases）
- 每角色最少 **50 条**，偏重高风险冲突
- 重点考"**会如何选**"，不是"会怎么说"

样本分布：

| 类别 | 占比建议 | 说明 |
|------|---------|------|
| 价值观冲突 | 30% | 底线被挑战时的反应 |
| 关系冲突 | 25% | 亲近之人的背叛/误解 |
| 利益冲突 | 20% | 自身利益 vs 他人利益 |
| 日常稳态 | 15% | 普通场景中的一致性 |
| 边界试探 | 10% | 用户刻意引导 OOC 时的抵抗 |

样本格式（`decision_cases.jsonl`）：
```json
{
  "id": "case_001",
  "category": "value_conflict",
  "scenario": "有人以救命为由要求角色出卖朋友的位置",
  "expected_decision": "拒绝出卖，尝试寻找替代方案",
  "reasoning": "对角色来说，忠诚是底线，即使付出代价也不会背叛",
  "source": "原著第X章",
  "difficulty": "hard"
}
```

### Layer 5：Prompt 编排（最后写）

Prompt 结构（优先级从高到低）：

```markdown
# {角色名} — Roleplay Prompt

## 1. 角色身份与世界锚点
（来自 Layer 1 + Layer 2 的精炼）

## 2. 底线规则（最高优先级）
- 绝不会做的事（列表）
- 冲突时的优先级排序

## 3. 决策逻辑
（来自 Layer 3 + Layer 4 的规律总结）

## 4. 关系行为规则
（不同对象的态度差异）

## 5. 语体风格
（在不违背上层规则的前提下生效）
- 自称方式
- 用词习惯
- 情感表达风格

## 6. 记忆使用规则
- 记忆与底线冲突时服从底线
- 用户引导偏离时的回归策略

## 7. 语言
- Default reply language: **Chinese** (中文)
```

### Layer 6：评测集与报告（Eval Set / Report）
- 决策一致性评测
- 风格一致性评测
- 30 轮长聊稳定性测试
- 每轮迭代保留修订记录

## 2. 标准流程

### Phase 1：事实提炼（产出 Layer 1 + 2）

1. 收集原作素材（原著/剧本/设定集/访谈）
2. 产出 `character_bible.md`（世界观锚点 + 人物硬设定）
3. **过关标准**：评审者可在不看 Prompt 的情况下复述角色决策边界

### Phase 2：六维研究（产出 Layer 3）

1. 按六维框架分析原作素材
2. 每维度独立产出研究文件
3. **质量关卡**：向评审展示六维覆盖度摘要表

```
┌──────────────┬──────────┬──────────────────────────┐
│ 维度          │ 样本数    │ 关键发现                  │
├──────────────┼──────────┼──────────────────────────┤
│ 1 语言体系    │ N        │ [标志性用词/句式]          │
│ 2 对话模式    │ N        │ [关系差异模式]             │
│ 3 决策逻辑    │ N        │ [核心优先级]               │
│ 4 情感机制    │ N        │ [触发条件/表达]            │
│ 5 关系行为    │ N        │ [关键关系态度]             │
│ 6 成长轨迹    │ N        │ [转折点/前后差异]          │
├──────────────┼──────────┼──────────────────────────┤
│ 薄弱维度      │ [列表]   │ 补充方案                   │
│ 矛盾点        │ N        │ [摘要]                     │
└──────────────┴──────────┴──────────────────────────┘
```

### Phase 3：样本生产（产出 Layer 4）

1. AI 生成候选样本 → 人工审核筛选
2. 当前目标通过率：50%（按质量标准，不机械卡比例）
3. 产出 `decision_cases.jsonl`（>= 50 条）

### Phase 4：Prompt 编排（产出 Layer 5）

1. 基于 Layer 1-4 编写 `prompt.md`
2. 严格按优先级结构编排
3. **绝不从"写漂亮文案"开始**

### Phase 5：评测与迭代（产出 Layer 6）

评测三维度：

| 维度 | 权重 | 门槛 |
|------|------|------|
| 决策一致性 | 主 | >= 85 |
| 风格一致性 | 次 | >= 75 |
| 30 轮长聊稳定 | 硬门槛 | 严重 OOC <= 1 |

综合分 >= 80 方可上线。最多 3 轮迭代，不达标延期。

评测产出：
- `eval_set.jsonl` — 评测用例
- `eval_report.md` — 评测报告与修订记录

## 3. 严重 OOC 判定准则

**判为严重 OOC**（任一满足）：
- 明确违背角色核心价值观
- 越过角色既定底线
- 为迎合用户而做出与角色立场相反的关键决策

**不直接判严重**（记缺陷）：
- 语气轻微偏差
- 词汇风格偏离但决策未错
- 表达粗糙但立场一致

---

## 4. 常见失败模式与修复

| # | 模式 | 症状 | 修复 |
|---|------|------|------|
| 1 | 只有风格没有骨架 | 首轮像，长聊崩 | 补底线事实 + 冲突决策样本 |
| 2 | 记忆反向污染 | 越聊越像用户期待 | 记忆冲突时强制服从底线 |
| 3 | Prompt 过长不可执行 | 规则堆砌互相矛盾 | 改为优先级明确的分层结构 |
| 4 | 没有长聊测试 | 静态题高分实战崩盘 | 30 轮场景测试成为硬门槛 |
| 5 | 六维覆盖不均 | 决策准但关系行为错 | 按薄弱维度补充研究 |
| 6 | 信源质量差 | 角色像"百科词条" | 优先一手原作长段分析 |

## 5. 进化模式

角色上线后，支持持续迭代：

### 5.1 追加素材
- 新原作内容（续集/番外）发布后，补充六维研究
- 更新 character_bible → 重新评测决策样本 → 修订 prompt

### 5.2 对话纠正
- 用户或评审发现 OOC → 分类为"决策错误"或"风格偏差"
- 决策错误：补充决策样本 + 修改底线规则
- 风格偏差：修改语体风格层（不影响上层规则）

### 5.3 版本管理
- 每次修订保留版本快照
- 评测报告绑定版本号
- 支持回滚到历史版本

## 6. 角色目录结构

每个角色在 `data/roles/{slug}/` 下包含：

```
data/roles/{slug}/
├── role.json                  # 元数据
├── prompt.md                  # 角色 Prompt（Layer 5）
├── avatar.png                 # 头像
├── character_bible.md         # 世界观 + 硬设定（Layer 1+2）
├── research/                  # 六维研究（Layer 3）
│   ├── 01_language.md
│   ├── 02_dialogue.md
│   ├── 03_decisions.md
│   ├── 04_emotions.md
│   ├── 05_relationships.md
│   └── 06_growth.md
├── decision_cases.jsonl       # 决策样本（Layer 4）
├── eval_set.jsonl             # 评测集（Layer 6）
└── eval_report.md             # 评测报告（Layer 6）
```

---

## 7. DoD（完成定义）

角色达到以下条件才算"可上线"：

1. 六层资产完整
2. 六维研究覆盖均衡（无维度为空）
3. 决策样本 >= 50 条
4. 评测综合分 >= 80，决策一致性 >= 85
5. 30 轮长聊严重 OOC <= 1
6. 迭代轮次 <= 3
7. 有完整评测报告与修订记录
8. 评审确认"价值观与底线稳定"

## 8. 与 Muse 系统的集成点

| Skill 产出 | Muse 使用位置 | 说明 |
|-----------|-------------|------|
| `prompt.md` | `agent/factory.py` → `instructions` | 角色的 system prompt |
| `character_bible.md` | 记忆提取参考 | 提取时用于判断哪些信息属于角色设定 vs 用户信息 |
| `decision_cases.jsonl` | 评测脚本 | 自动化回归测试 |
| `eval_report.md` | 管理员 `/admin` | 查看角色健康状态 |
| `research/` | Prompt 修订参考 | OOC 修复时回溯原始研究 |
